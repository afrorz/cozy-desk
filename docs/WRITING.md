# Cozy Desk の記事の書き方

白デスク・淡色デスク(#淡色界隈・#デスクレシピ)が好きな人に向けて、白と淡い色のガジェットを紹介するサイト。
収益は紹介料(楽天・Amazon・Yahoo!ショッピング)。読んだ人が「同じ物を買いたい」と思え、迷わず買える記事にする。

## 記事は2種類

| kind | 中身 |
|---|---|
| `new` | 新作1つを紹介する。`origin: jp`(日本の発表)は、その物を買うボタン(`q:`・`stores:`)をつける。`origin: world`(海外の発表)は、記事末に「日本で買える？使える？」(`japan:`)を書き、近い物を日本で探すボタン(`alt_q:`)をつける。毎朝の手順は `docs/DAILY.md` |
| `buy` | 日本で今買える白・淡色の物を3〜5個まとめる(`products:`)。1つずつ買うボタンがつく |

## 週の割り振り(2026-11-04 本人と組み直した)

- `new` は毎日1本(国内と海外を半々)。毎朝5時に自動で書いて公開する(`docs/DAILY.md`)。合う新作が無い日は書かない
- `buy` は週1本
- `buy` は1本7〜8点のまとめ。2周目からは新しい記事より、今の記事の物と値段の入れ替えを優先。新しく作るなら種類をまたぐ切り口(「ピンクだけでそろえる」「10,000円以下で白くする」など)
- 選び方・付け方の説明が多い物(間接照明など)は、日本で買える物でも1商品1記事にしてよい
- X では、まとめの物も1つずつ見せ、リンクはその物の場所(`/p/<日付を除いた記事の名前>/#item-番号`)へ

## いちばん大事なこと: このサイトの目的は紹介料

載せる物・記事の形・言葉は、「読んだ人がボタンを押して買うか」で決める(2026-10-31 本人)。

- **`buy` に載せる物は、楽天・Amazon・Yahoo!ショッピングの「1つ以上」で、メーカーか正規の店(公式ストア・大手量販店・PC専門店)が売っている物。** 3つ全部そろっている必要はない。1つでも買えれば載せる(2026-10-31 本人)。どこでも売っていない物(IKEA など)は、代わりの無いときだけ載せ、ボタンの代わりに公式ストアのリンクを書く
- 売っているストアが分かったら、物ごとに `stores: [rakuten, yahoo]` のように書く。書いたストアのボタンだけが出る(無い店のボタンを押させて、押し損にしないため)。書かなければ3つ出る
- メーカーの日本公式ストアが `config/site.yaml` の `affiliate.a8` にある(A8 で提携済みの)店なら、`official: {store: 名前, url: 日本向けの商品ページ}` も書く。「公式ストアで見る」が先頭に出る。型番・色が同じページか確かめる。a8 に無い店は書かない
- `q` は、3つのストアの検索でその物が一番上に出る言葉にする(型番＋色)。書いたら実際に検索して確かめる
- `new` の `alt_q` は、3つのストアで実際に売っている近い物に当たる言葉にする

## 絶対に破らない決まり(Gadget Terminal と同じ)

- **公式ページで確かめた事実だけを書く。** 値段・大きさ・重さ・色の名前・つなぎ方は、メーカー公式ページか公式ストアで確かめる。確かめられなければ書かない
- **値段には「掲載時点」とつける。** 日本で買える物は円で、メーカー公式ストアか公式の希望小売価格。量販店の一時的な値引きは書かない
- **色の名前はメーカーの呼び方を使う**(例: オフホワイト、ローズ、ミルクティー)。`hex` は公式写真の見た目に近い淡い色を選ぶ
- **使ってみた感想を書かない。** 「使ってみると」「手に取ると」「実際に座ると」は禁止。編集部は使っていない
- **「技適」という言葉と、専門用語を出さない**(2026-10-31 本人判断。GT とはここが違う。読む人は「技適」と言われてもわからない)
  - 裏では GT と同じく、無線の物が日本向けの正規品か(技適があるか)を確かめる。書くときは「日本の正規品」「日本の公式ストアで販売」のような、ふつうの言葉にする
  - 日本向けか確かめられない無線の物は、なるべく選ばない。海外の新作(`new`)なら `japan:` に「無線で使うなら、日本向けの発売を待つのが安心です」のように、やさしく書く
  - 規格の言葉も言いかえる: 「2.4GHz Wi-Fi」→「スマホのアプリで操作」、「TRS・RCA・XLR」→「ケーブルでもつなげる」、「USB Type-A」→「USB でつなぐ」。大きさは cm で丸める
- **動く映像はメーカー公式 YouTube 動画の3秒・音なしの切り出しだけ**(1記事3カットまで・出典つき。`scripts/add_clip.py`、2026-11-04 本人「メーカー動画を使えるところは使いたい」)。画像を自分のサーバーに置かない決まりの、ただ一つの例外
- **画像はメーカー公式ページ・公式ストアの画像URLを直接書く**(ダウンロードしない)。出典を必ず書く。ニュースサイト・個人ブログ・Amazon の画像は使わない。URL が実際に開けることを確かめる(Shopify の `cdn/shop/files/...` など)
- 公式の写真の背景が灰色で白い枠から浮くときは、配信の仕組みで背景を消せることがある。Bellroy(imgix)は URL の後ろに `?bg-remove=true&fm=png&w=800` を足すと背景が透明になる(2026-11-02)
- 煽らない。感嘆符と絵文字を使わない
- 円換算は書かない(海外の値段はドルのまま)
- 円の値段は「29,980円」のように数字とカンマで書く。「2万9,980円」のように万を使わない(2026-11-14 本人)

## タイトル(2026-11-01 本人指摘)

- 「日本で今買える◯つ」を売りにしない。読む人は買えるのが当たり前だと思っている。「日本で買える」「正規品」は本文と各商品の欄に書く
- 置いたときの景色・気分・かわいさから入る。数は「◯選」のように後ろへ
- 「A、B◯つ。C」のように読点と句点で言葉を並べる形は、AI が書いた文に見えるので使わない
- 例: ×「白いPCスピーカー、日本で今買える8つ。モニターの両脇にちょこんと置く」 → ○「モニターの横に、白くて小さなスピーカー。デスクがすっきり見える8選」
- **新作の記事(kind: new)は30字くらいまで**(2026-11-06 本人)。前半にワクワクする一言(楽しくなる・おしゃれになる)、そのあとにメーカー名と色、いちばんの違いを1つ。比喩や景色の描写を長く書かない。検索結果や X のカードで30字前後から先は切れる
- 例: ×「黒いヘッドホンが浮いていた白い机に、ラベンダー色をひとつ。ゼンハイザー「MOMENTUM 5 Wireless」の新色は、ケースまで同じ色」(約60字) → ○「白デスクで浮かない。ゼンハイザーのラベンダー、ケースまで同じ色」(31字)
- 本文の最初の見出しは「シロネの推しポイント」(11/6 本人。「こんな毎日に」は押し付けがましいのでやめた。build.py がシロネの顔をつける)。困りごとを並べるより、この物がある毎日の一場面と、何がちょっと楽しくなるかを書く。**ただし、誰にでもある「あるある」の困りごと(電池が気づいたら切れている、速く充電できているかわからない、など)が解けるなら、書き出しではなく後ろで「〜なので、〜が起きにくい」のうれしさとして必ず1文入れる**(11/6 本人)

## 文の調子

- 短く、やわらかく。「〜です・〜ます」。むずかしい言葉は使わない(「エルゴノミクス」→「体に合わせて調整できる」)
- 何がかわいいか・白デスクにどう合うかを、色・形・素材の事実から書く
- `summary` は1〜2文。検索結果にそのまま出る

## ファイル

`content/posts/YYYY-MM-DD-<英小文字の短い名前>.md`。URL は日付を除いた `/p/<英小文字の短い名前>/` になる(2026-11-02 本人。まとめ記事を直して使い続けても古く見えないように)。名前は他の記事と重ならないようにする(重なるとビルドが止まる)。日付つきの古い URL には転送のページが自動で置かれる。front matter の値に `:` が入るときはダブルクォートで囲む。

```yaml
---
title: "白いPCケース、日本で今買える5つ。ガラス越しに淡く光る"
date: 2026-10-31
category: pc          # desk chair pc monitor mouse keyboard speaker gear interior
kind: buy             # new か buy
summary: "…"
thumbnail: "https://…"           # 一番目立つ公式画像。無ければ書かない
thumbnail_alt: "…"
thumbnail_credit: "NZXT 公式サイト"
thumb_fit: true                  # 切り抜き写真(白背景の製品画像)なら true、部屋の写真なら書かない
# inside: "https://…"            # (products の中に書く)中を開いた公式写真。{{features}} の札で大きく出る。ポーチなど中の作りが大事な物は必須(2026-11-02 本人「中の仕切り画像はマスト」)。別の色の写真なら説明の文に「(中の写真は別の色)」と書く
# updated: 2026-12-01             # 値段や物を入れ替えた日。画面に「更新」と出て、検索エンジンにも更新日として伝わる
# board_style: note             # まとめ記事の看板を手帳デコ風(物の写真を方眼ノートに貼った形)にする。今はガジェットポーチの記事だけ(11/2 本人)。札の文字は題の「。」の前後、合わなければ board: {lead: …, title: …}
colors:                          # その記事の物の色(サイトの一覧に丸で出る)
  - {name: ホワイト, hex: "#F7F6F2"}
products:                        # buy のとき
  - name: "NZXT H6 Flow ホワイト"
    image: "https://…"           # 公式の製品画像
    image_credit: "NZXT 公式サイト"
    price: "19,800円(掲載時点・公式ストア)"
    colors: [{name: ホワイト, hex: "#F7F6F2"}]
    note: "1〜2文。何がかわいいか、白デスクにどう合うか"
    jp: "日本の正規販売品 ・ ATX 対応"     # 日本での買いやすさ・つなぎ方・大きさなどを、ふつうの言葉で
    q: "NZXT H6 Flow ホワイト"   # 楽天・Amazon・Yahoo で検索する言葉。型番＋色が確実
    # category: gear             # 記事の種類と違う物のときだけ(デスクレシピなど)。種類のページの「色で選ぶ」に並ぶ
    # 色の系統(白・ピンクなど「色で選ぶ」のボタン)は hex から自動。外れるときだけ colors に tone: ピンク のように書く
    # facets: {width: 160cm以上, shape: 昇降}  # デスクだけ必須。種類ページは色でなく横幅・形で選ぶ(値は config/site.yaml の facets)。ガジェット好きは昇降式が多いので、机を足すときは昇降を優先
    # 同じ物を別の記事で使い回すときは name を一字一句そろえる(種類のページで重ならないように)
sources:
  - {name: NZXT 公式サイト, url: "https://…"}   # 確かめたページを全部
---

本文(Markdown)。buy のときは、選び方(何を見て選ぶか)を書く。
各製品の説明は products に書くので、本文で同じことを繰り返さない。

選び方は「買ったのに使えない」を防ぐ情報を、具体的な数字で書く(2026-11-01 本人の指摘。PCケースで「サイズや空冷・水冷の対応も伝えたい」)。
- 例: PCケースなら、入るマザーボードの大きさ・CPUクーラーの高さ・水冷のラジエーター・グラボの長さ・置き方。数字は公式の仕様から
- 選び方の中で物の名前を出したら、行の終わりに `{{items:3,2}}` のように物の番号(products の上から何番目か)を書くと、小さな写真が並ぶ。押すと売っている最初の店のページが開く(2026-11-02 本人)
- 物を大きさなどで分けて見せたいときは、`{{sizes` の行のあとに1行ずつ「札|見出し|説明|番号,番号」を書き、`}}` で閉じる。箱が横に並び、物が写真・短い呼び名(products の `short:`)・大きさ(jp の「◯×◯×◯cm」)・店のリンクで1行ずつ出る(2026-11-02 本人「もっといい感じにまとめて」。例はガジェットポーチの選び方1)
- 物ごとの説明が長いときは `{{features` の行のあとに1行ずつ「見出し|説明|番号:特徴の文;番号:特徴の文」を書き、`}}` で閉じる。分け方ごとの色の帯を縦に積み、物の札(写真・短い呼び名・説明・店のリンク)が並ぶ。説明が長くても崩れない(2026-11-02。例はガジェットポーチの選び方2)
- 物×できること(立つ・開く・吊るせる など)を見比べるなら `{{matrix`(1行目に列の名前「A|B|C」、2行目から「番号:○|一言|」。空はなし)。強さの段(水への強さなど)を見せるなら `{{drops`(1行に「見出し|説明|番号,番号」、上から強い順)。どちらも物を押すと店のページへ(2026-11-02。例はガジェットポーチの選び方3・4)
- 選び方ごとに中身に合った形を選ぶ。全部を同じ形にしない(2026-11-02 本人「同じだとデザインが崩れる。ここはここで最適なデザインを」)
- 載せた物の仕様を並べた比べ表をつける。 比べ表の名前の欄には `{{cell:3}}` のように物の番号を書く。小さな写真・短い呼び名・店のリンクになる(2026-11-02 本人)物ごとの `jp:` にも寸法・重さ・対応を入れる
- 選び方が長いときは、短い前置きのあとに `<!-- after-items -->` と書く。そこから後ろは商品の下に出る(商品が下に押しやられないように)。前置きに `[買う前に見る所](#erabikata)` のようなリンクを置き、見出しに `{#erabikata}` をつける
- ページの構成は「前置き → 商品 → 買う前に見る所 → 比べ表」で決まり(2026-11-01 本人決定)。競合の多くは選び方が先だが、商品を先にする。商品の上に「迷ったらこれ」の早見を置く案はモックを見たうえで見送り。再提案しない
```

## 書いたら確かめる

`python scripts/build.py` が通ること。

- `card_items: [1, 3, 7, 9]`(まとめ記事): 記事一覧のカードに、その番号の物を4つ並べる(色・メーカーがばらけるように。図や文字の入った写真、時々開かない写真は避ける)。11/3 から全まとめ記事に入れている。新しいまとめ記事にも入れる。すき間の色は説明の欄と同じ
- `board_style: scene` と `board_image: "/assets/boards/<名前>.jpg"`(まとめ記事、任意): 本人が Gemini で作った部屋の絵の左側に、題の札と物の写真を乗せる看板。**Gemini に渡す文は docs/GEMINI_BOARD.md の共通の文から作る**(床の色・椅子・左半分・大きさの決まりあり)。絵は横1800px に縮めて assets/boards/ に置く。頼まれた記事にだけ入れる
- `{{bars ...}}`: 1行に「番号|数|表示」。物ごとの横棒(厚さ・重さなどの数を比べる)。`{{drops:updown}}`(上下の矢印)・`{{drops:battery}}`(電池)で段の印を変えられる
- `{{helper:1}}`: 本題の物ではないが、一緒に使うと悩みが解決する物(例: 賃貸で壁に貼りたくない→突っ張り柱の部品)。記事の `helpers:` に name・tag・image・image_credit・price・note・q を書く。店のボタンつきの札になる(2026-11-05 六角形ライト)
- `{{monfit}}`: モニターと机の横幅(80〜140cm)を選ぶと、正面から縮尺どおりに置いた図と「左右に◯cm空く・台座の奥行で手前に◯cm残る」が出る。products に `mon: {w: 幅cm, h: 一番高い所cm, d: 台座の奥行cm}`(公式の値)を書いた物が並ぶ(2026-11-06 白いモニター)
- `{{wallsize}}`: 六角形のパネル(幅23×高さ20cm)を、24インチのモニターと同じ縮尺の壁に自分で並べる図(動きは assets/wallsize.js)。点線を押すと足す・押すと消す・色をぬる、ひな形3つ。枚数・大きさ・Shapes で足りるセットと値段の目安が出る(六角形ライトの記事用。値段を変えたら wallsize.js の plan も直す)
- `board_glow:`(看板が scene のとき): 色ごとに `{name, hex, image}`。看板に「光の色」のボタンが出て、押すと image の絵にふわっと切り替わる。image は元の看板の絵から、光る物だけ色を変えて作る(六角形ライトの記事)
- 写真の置き場所が縮める指定に対応していれば、build.py の sized() が自動で縮める(Shopify・imgix・ロジクール・Fractal・Creative。11/3 キーボードの記事が 13.6MB→0.34MB)。新しいメーカーの写真が重いときは、URL に指定を足して縮むか試して sized() に足す
